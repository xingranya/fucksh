我的做法：三层掐断

为什么要两层模块
应用层
L1~L4 拦截，让采集根本不发生
L1 出口返回 true（伪装上报成功）· L2 总闸返回空对象不采集 · L2 门控权限判断返回 false · L3 定位不启动 · L4 不写本地库，并在启动时清空历史积压
LSPosed 2.x
内核层
按 uid 阻断全部出站，连 native 层一起拦
iptables / ip6tables 对 uid 10100 全部 REJECT，每 60 秒自愈重加规则；netd 重启清了规则也能自己补回来
KernelSU
为什么不能只做一个：它内嵌的百度定位 SDK 网络收发在 JNI 里， 整个 APK 里 java.net.Socket 零引用 —— Java 层没有可 hook 的点， 只能靠按 uid 的内核阻断兜底。
05

两个文件分别干什么

可以只装一个
A
SystemHelperBlocker-KernelSU-1.0.zip
刷新到 KernelSU 的内核模块。
作用：把这个 uid 的所有出站流量直接 REJECT，数据一个字节都发不出去。
单独可用：是。只装它就已经彻底断网，缺点是不采集也拦不住（数据仍在本地生成）。
B
SystemHelperBlocker-Xposed-1.0.apk
装在 LSPosed 里的模块（libxposed API 102）。
作用：在它自己的进程里把采集、定位、落库全部短路，出口伪装成上报成功，不留补报。
单独可用：是。装它之后数据连生成都不会发生。
都装 = 最干净：应用层先让采集不发生，内核层兜底防漏。两层通过共享目录联动， 内核模块的「操作」按钮可以一次看到两层的状态、心跳和拦截计数。
